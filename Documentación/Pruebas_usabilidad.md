## 1. Objetivo de las pruebas

Evaluar la facilidad de uso, claridad visual, navegación y autonomía operativa de la aplicación LabSound, verificando que un usuario externo pueda desarrollar un experimento de ondas sonoras sin necesitar asistencia técnica de los desarrolladores.

Las pruebas buscan identificar dificultades de interacción y oportunidades de mejora en la experiencia del estudiante.

## 2. Descripción de la aplicación

LabSound es un laboratorio virtual para estudiantes de primero medio que permite visualizar ondas sonoras, analizar su espectro de frecuencias y registrar mediciones mediante una interfaz web.

La aplicación incorpora:

- Captura de sonido mediante micrófono.
- Modo demostración de 440 Hz.
- Gráfico de onda temporal.
- Gráfico de espectro de frecuencias.
- Indicadores de frecuencia dominante, nivel relativo y frecuencia de muestreo.
- Tabla de mediciones con estadísticas.
- Controles de selección de frecuencia de referencia.

**Enlace:** https://proyecto-innovacion-lab.netlify.app/

## 3. Metodología de evaluación

Se propone realizar una prueba de usabilidad con al menos un usuario externo al equipo de desarrollo, preferentemente un estudiante del público objetivo.

El usuario deberá interactuar con LabSound sin recibir instrucciones adicionales sobre el funcionamiento de los controles.

El evaluador observará el desarrollo de cada actividad y registrará:

- Si la tarea fue completada.
- Si el usuario necesitó ayuda.
- Tiempo aproximado de ejecución.
- Dificultades encontradas.
- Comentarios del participante.

## 4. Procedimiento de evaluación

### Prueba 1. Acceso a la aplicación

**Objetivo:** Comprobar que el usuario puede ingresar a LabSound e identificar su propósito.

**Procedimiento:**
1. Abrir el enlace de la aplicación.
2. Observar la pantalla principal.
3. Identificar el nombre del laboratorio.
4. Explicar qué fenómeno permite estudiar.

**Resultado esperado:** El usuario comprende que LabSound permite estudiar la relación entre frecuencia y tono.

### Prueba 2. Identificación de controles

**Objetivo:** Evaluar la claridad de los botones principales.

**Procedimiento:**
1. Localizar el botón «Activar micrófono».
2. Identificar el botón «Modo demo 440 Hz».
3. Localizar los botones «Detener» y «Registrar medición».
4. Explicar para qué sirve cada control.

**Resultado esperado:** El usuario identifica los controles y comprende sus funciones.

### Prueba 3. Inicio del experimento

**Objetivo:** Verificar que el usuario puede comenzar el análisis sin asistencia.

**Procedimiento:**
1. Seleccionar el modo demostración de 440 Hz.
2. Comprobar que el sistema indique que está activo.
3. Observar los gráficos de la aplicación.
4. Identificar la frecuencia dominante.

**Resultado esperado:** El usuario inicia correctamente el experimento y observa una frecuencia cercana a 440 Hz.

### Prueba 4. Interpretación de gráficos

**Objetivo:** Evaluar la comprensión de las visualizaciones científicas.

**Procedimiento:**
1. Observar el gráfico «Onda en el tiempo».
2. Observar el gráfico «Espectro de frecuencias».
3. Identificar el indicador de frecuencia dominante.
4. Explicar qué información representa cada elemento.

**Resultado esperado:** El usuario reconoce la representación temporal y frecuencial del sonido.

### Prueba 5. Registro de mediciones

**Objetivo:** Comprobar que el usuario puede registrar resultados.

**Procedimiento:**
1. Mantener activo el modo demostración.
2. Presionar «Registrar medición».
3. Comprobar que aparece un registro en la tabla.
4. Repetir el procedimiento hasta completar cinco mediciones.
5. Observar los indicadores estadísticos.

**Resultado esperado:** El usuario registra cinco mediciones y localiza el promedio, la desviación estándar y el error porcentual.

### Prueba 6. Cambio de referencia

**Objetivo:** Evaluar la comprensión de los controles de referencia.

**Procedimiento:**
1. Localizar los botones de 220, 440 y 880 Hz.
2. Seleccionar una frecuencia de referencia diferente.
3. Observar el indicador de error.
4. Explicar qué cambió en el cálculo.

**Resultado esperado:** El usuario identifica que se modifica la frecuencia de referencia y comprende que el tono generado por el modo demostración continúa siendo de 440 Hz.

### Prueba 7. Finalización del experimento

**Objetivo:** Verificar que el usuario puede detener el análisis correctamente.

**Procedimiento:**
1. Presionar «Detener».
2. Comprobar que la aplicación indique que el audio está inactivo.
3. Consultar las mediciones previamente registradas.
4. Identificar el botón para limpiar la tabla.

**Resultado esperado:** El usuario finaliza la adquisición sin ayuda y puede revisar o eliminar las mediciones.

### Prueba 8. Adaptación a dispositivos móviles

**Objetivo:** Evaluar la presentación de la interfaz en pantallas pequeñas.

**Procedimiento:**
1. Abrir LabSound desde un teléfono.
2. Revisar la distribución de controles.
3. Comprobar la legibilidad de los gráficos.
4. Registrar una medición.
5. Verificar que los botones sean accesibles.

**Resultado esperado:** La interfaz se adapta al dispositivo sin superposición de elementos ni pérdida de funcionalidades.

## 6. Indicadores de usabilidad

Para evaluar los resultados se utilizarán los siguientes indicadores:

**Porcentaje de tareas completadas:**

(Tareas completadas / Total de tareas evaluadas) × 100.

**Porcentaje de tareas realizadas sin ayuda:**

(Tareas completadas sin asistencia / Total de tareas evaluadas) × 100.

**Número de dificultades detectadas:**

Cantidad de problemas observados durante las interacciones.

**Tiempo de ejecución:**

Tiempo aproximado requerido para completar cada actividad.

Los resultados permitirán identificar las áreas de la interfaz que necesitan modificaciones.

## 7. Mejoras propuestas

A partir de la inspección de la interfaz se proponen las siguientes mejoras para su posterior evaluación:

1. Incorporar instrucciones numeradas para orientar el experimento.
2. Añadir escalas numéricas más detalladas en los gráficos.
3. Diferenciar con mayor claridad la frecuencia de referencia y la frecuencia generada.
4. Incorporar una comparación final entre mediciones.
5. Mejorar las indicaciones de finalización del experimento.
6. Evaluar la legibilidad de tablas y gráficos en teléfonos móviles.

Estas mejoras son propuestas y no se consideran implementadas.

## 8. Evidencias requeridas

Después de ejecutar las pruebas se deberán incorporar evidencias como:

- Captura de LabSound en computador.
- Captura de LabSound en teléfono.
- Captura de los gráficos con el modo demostración activo.
- Captura de la tabla con cinco mediciones.
- Registro de observaciones del participante.
- Evidencia de las correcciones realizadas, cuando corresponda.

## 9. Conclusión

La revisión del código fuente permite identificar una interfaz organizada en paneles, con controles interactivos, gráficos científicos y reglas de adaptación a diferentes tamaños de pantalla.

Estas características constituyen una base para desarrollar una experiencia educativa autónoma.

Sin embargo, la usabilidad real debe validarse mediante la observación de usuarios externos durante la ejecución de las tareas propuestas.

La aplicación de este protocolo permitirá identificar dificultades concretas y fundamentar futuras decisiones de diseño UX/UI.
